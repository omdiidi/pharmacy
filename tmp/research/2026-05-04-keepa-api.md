> Date: 2026-05-04

## Summary

Keepa is an Amazon price-history database with a paid HTTP/JSON API. There is **no official TypeScript SDK** — the only first-party SDK is Java (`keepacom/api_backend`). PharmaDash will implement a thin TypeScript client.

The API uses a **token-bucket** model: every request costs N tokens; tokens regenerate at a fixed per-minute rate determined by plan tier; unused tokens expire 60 minutes after creation. The `$54/mo` (€49/mo) entry tier yields **20 tokens/min** (~1,200 product lookups/hour). Authentication is a single `key` query parameter — no headers, no OAuth.

Price/rank/offer history is delivered as packed `int[]` arrays in a Keepa-specific encoding: minute-resolution timestamps (`keepaMinutes`) interleaved with cents-denominated values, with `-1` meaning "no offer / out of stock." Each array index in the `csv` field maps to a specific data type (Amazon price, NEW marketplace, NEW_FBA, BUY_BOX_SHIPPING, SALES rank, etc.).

The Tracking API supports **push webhooks** for price-threshold and stock-change events — this is the mechanism Repricer will subscribe to.

## 1. Authentication

**Mechanism:** Single API key, passed as a query string parameter `key=<KEEPA_API_KEY>` on every request. No headers, no Bearer tokens, no signatures, no OAuth.

```
GET https://api.keepa.com/product?key=YOUR_KEY&domain=1&asin=B07XJ8C8F5
```

**Where to get the key:** [keepa.com/#!api](https://keepa.com/#!api) → log in → Subscriptions tab. The key appears once you've subscribed to a paid tier. There is no free API tier (the free Keepa account gives browser-extension features only).

**Plan tiers** (as of 2026; verify before purchase):

| Plan | Cost | Tokens/min | Tokens/hour (steady state) | Notes |
|---|---|---|---|---|
| Starter | €49/mo (~$54) | **20** | 1,200 | Lowest paid tier. PharmaDash is here. |
| Higher tiers | €99–€999+/mo | 50 → 2,000+ | scaled | For high-volume scrapers / aggregators. |

**Token bucket mechanics:**
- Tokens regenerate at `refillRate` per minute (e.g. 20/min on Starter).
- Maximum bucket size = `60 * refillRate` (one hour of regeneration; 1,200 on Starter).
- Unused tokens **expire 60 minutes after creation** — you cannot stockpile.
- Every response includes headers (and a `tokensLeft` field in JSON body) telling you the current balance. Burning tokens past zero returns HTTP 429 with a `refillIn` (ms) value.

**Storage in PharmaDash:** `KEEPA_API_KEY` belongs in the Render `pharm1-shared` envVarGroup. Add to `.env.example`. Never log the key. Wrap requests in a single `lib/keepa/client.ts` module so the key never leaks into agent prompts.

## 2. Token Economy

Every endpoint has a baseline cost; some endpoints scale with parameters (e.g. `offers`, `buybox`).

| Endpoint | Base cost | Scales with | Notes |
|---|---|---|---|
| `/product` (basic, history only) | **1 token / ASIN** | `history`, `stats`, `update` are free | Cheapest path. |
| `/product` (with `offers=20..100`) | **+1 token** when offers requested | offer count does not change cost | Adds live + historical offer breakdown. |
| `/product` (with `buybox=1`) | **5 tokens / request** | overrides base | Buy Box history with shipping. |
| `/product` (with `rating=1`) | +1 token | | Live rating + review count. |
| `/search` (product) | **1 token / page returned** | each page = up to 40 ASINs | `update` and `history` add cost like `/product`. |
| `/search` (category) | **1 token** | | Returns category nodes matching term. |
| `/category` (lookup) | 1 token | | |
| `/bestsellers` | **50 tokens** | | Category root may have up to 100,000 ASINs. |
| `/deal` | **5 tokens / page** | each page up to 150 deals | Cheapest discovery path for Research Analyst. |
| `/seller` | **1 token / sellerId** | `storefront=1` makes it 5 tokens | |
| `/tracking?type=add` | **0 tokens** to add | tracking emissions are free | Notification webhooks delivered free. |
| `/tracking?type=notification` | 0 tokens | poll-mode for notifications | |
| `/token` | 0 tokens | | Read current balance. |

> Sources: [keepa.com/#!api](https://keepa.com/#!api), [keepaapi.readthedocs.io](https://keepaapi.readthedocs.io/en/latest/api_methods.html), and [DataVirtuality Keepa connector docs](https://docs.datavirtuality.com/connectors/keepa-api-information). Costs may shift; verify on first integration day.

**Caching to save tokens:** Keepa explicitly caches identical graph-image requests for 90 minutes per user. For `/product`, an "update" parameter <hour-since-last-fetch threshold returns cached data **without burning tokens** if the data is still fresh — the `update` param specifies max age in hours; passing `update=24` only re-fetches if Keepa's last refresh was >24 h ago.

**PharmaDash budget math (Starter tier, 20 tokens/min = 1,200/hr):**
- Repricer: ~30 listings × 1 token (basic /product, `update=2`) = 30 tokens / 2 hours = **trivial.**
- Research Analyst: 1 `/deal` page (5 tokens) + 10 product lookups (10 tokens) = 15 tokens / daily run = **trivial.**
- Bestsellers crawl: 50 tokens × 5 categories = **250 tokens** — significant; do once per week.
- Webhook tracking on 30 listings: zero recurring token cost.

**Headroom:** Easily fits Starter tier. Phase 2 doesn't need a higher plan unless we add a discovery crawler.

## 3. Endpoints We Need

Base URL: `https://api.keepa.com/<endpoint>`. All requests are GET except `/deal` and `/tracking?type=add` which are POST with JSON body. All requests include `key=<API_KEY>`.

### 3.1 `/product` — full price/rank/offer/seller history for an ASIN

```
GET /product?key=K&domain=1&asin=B07XJ8C8F5
            &history=1     # include price history arrays (free; default 1)
            &stats=180     # include 180-day stats summary
            &offers=20     # include 20 most-recent offers (optional; +1 tok)
            &buybox=1      # include buy box history (optional; 5 tok total)
            &rating=1      # include rating history (optional; +1 tok)
            &update=2      # only refetch if cache > 2h old (saves tokens)
            &days=90       # truncate history to last 90 days (smaller payload)
```

Multiple ASINs: `asin=ASIN1,ASIN2,ASIN3` (comma-separated, max 100 per request — each costs its own tokens).

`domain` enum: `1`=US, `2`=GB, `3`=DE, `4`=FR, `5`=JP, `6`=CA, `8`=IT, `9`=ES, `10`=IN, `11`=MX, `12`=BR. Kaleem = US = `1`.

**Response shape (top level):**
```jsonc
{
  "timestamp": 28891232,            // server keepaMinutes
  "tokensLeft": 1187,
  "refillIn": 5421,                 // ms until next token granted
  "refillRate": 20,
  "tokenFlowReduction": 0,
  "tokensConsumed": 1,
  "processingTimeInMs": 142,
  "products": [ Product, ... ]
}
```

### 3.2 `/search` — keyword search

```
GET /search?key=K&domain=1&type=product&term=tinactin&page=0
            &stats=90&history=0&update=24
```

Returns up to **40 ASINs per page** (`page` 0–9 = max 400 ASINs). Each page costs 1 token plus product-history overhead.

For category search: `type=category&term=fungal+cream` → returns category node IDs.

### 3.3 `/bestsellers` — by category

```
GET /bestsellers?key=K&domain=1&category=3760931  # Health & Household root
```

Returns flat ASIN list, daily-refreshed. **50 tokens per call.** Use sparingly; cache results for 24h.

### 3.4 `/deal` — products with recent price drops

POST with JSON body. Cheapest opportunity-discovery endpoint:

```
POST /deal?key=K
Content-Type: application/json
{
  "page": 0,
  "domainId": 1,
  "includeCategories": [3760931],   // Health & Household
  "priceTypes": [0, 1, 18],         // AMAZON, NEW, BUY_BOX_SHIPPING
  "deltaPercentRange": [10, 100],   // 10% - 100% drop
  "salesRankRange": [1, 50000],
  "minRating": 30,                   // 3.0 stars (0-50 scale)
  "isRangeEnabled": true,
  "isFilterEnabled": true,
  "filterErotic": true,
  "hasReviews": true,
  "isOutOfStock": false,             // we want deals on in-stock items
  "dateRange": 1,                    // 0=day, 1=week, 2=month, 3=90d
  "sortType": 4                      // 4 = % drop desc
}
```

Returns `dr` (deals array) up to **150 per page**, plus `categoryIds`, `categoryNames`, `totalDealsFound`. **5 tokens / page.**

### 3.5 `/token` — current token balance

```
GET /token?key=K
```

Free. Returns `{ tokensLeft, refillIn, refillRate, tokenFlowReduction, timestamp }`. Use for health checks and to gate burst requests.

### 3.6 `/tracking` — register watch + manage subscriptions

| `type=` | Method | Purpose |
|---|---|---|
| `add` | POST | Create/update tracking on an ASIN with thresholds. |
| `get` | GET | Read one tracking config. |
| `list` | GET | List all our trackings (~paginated). |
| `remove` | GET | Unsubscribe from one ASIN. |
| `removeAll` | GET | Nuke all trackings. |
| `notification` | GET | Poll-mode: pull notifications since `since` timestamp. |
| `webhook` | GET | Set/update the webhook URL where push notifications go. |

```
POST /tracking?key=K&type=add
Content-Type: application/json
{
  "asin": "B07XJ8C8F5",
  "ttl": 8760,                         // 1 year in hours
  "expireNotify": false,
  "mainDomainId": 1,
  "updateInterval": 1,                 // hours between Keepa-side checks
  "metaData": "pharm1:tinactin:30g",   // our own correlation ID (max 500ch)
  "thresholdValues": [
    {
      "thresholdValue": 1500,          // notify if Buy Box drops to ≤$15.00
      "domain": 1,
      "csvType": 18,                   // BUY_BOX_SHIPPING
      "isDrop": true
    }
  ],
  "notifyIf": [
    {
      "domain": 1,
      "csvType": 18,
      "notifyIfType": 0                // 0 = OUT_OF_STOCK
    },
    {
      "domain": 1,
      "csvType": 18,
      "notifyIfType": 1                // 1 = BACK_IN_STOCK
    }
  ],
  "notificationType": [false, false, false, false, false, true, false, false],
  // Index 5 = API (webhook). Order: EMAIL, TWITTER, FB_NOTIF, BROWSER, FB_MSG, API, MOBILE, DUMMY
  "individualNotificationInterval": 1440  // rearm every 24h max
}
```

### 3.7 Webhook delivery (the mechanism Repricer subscribes to)

After we register a webhook URL via `GET /tracking?type=webhook&url=<URL>`, Keepa POSTs notification objects to that URL when triggers fire.

**Delivery contract:**
- Method: HTTP POST
- Body: single Notification JSON object (one per fire — not batched)
- Expected response: HTTP 200 within ~30 seconds
- Retry: **one retry with 15-second delay** if first delivery fails. After that, dropped.
- No HMAC signing (verify by either IP allowlist if Keepa publishes one, or by treating `metaData` as a HMAC token we set).

We MUST design idempotency: store `(asin, csvType, keepaTime)` tuple as a uniqueness key in our `keepa_notifications` table; ignore duplicates.

## 4. Response Shapes (TypeScript-ready)

### 4.1 Time encoding

Keepa timestamps are in **minutes since a fixed epoch**, called `keepaMinutes` or `keepaTime`. Convert:

```ts
// keepaMinutes -> Unix ms
export const keepaMinutesToUnixMs = (k: number): number => (k + 21564000) * 60_000;
// Unix ms -> keepaMinutes
export const unixMsToKeepaMinutes = (ms: number): number => Math.floor(ms / 60_000) - 21564000;
```

Constants verified across [keepa Python SDK](https://github.com/akaszynski/keepa) and [Java SDK KeepaTime](https://github.com/keepacom/api_backend).

### 4.2 CSV format (the packed history arrays)

Each `Product.csv` is an `int[][]` indexed by `CsvType` (see below). Each inner array is a flat list of pairs:

```
csv[CsvType.AMAZON] = [t0, p0, t1, p1, t2, p2, ...]
                       └──┬──┘ └──┬──┘ └──┬──┘
                       pair 0  pair 1  pair 2
```

- `t` is a `keepaMinutes` value (use converter above).
- `p` is an integer in **smallest currency unit** (cents for USD/GBP/EUR; yen for JPY).
- `p === -1` means **no offer / out of stock** at that time.
- Newest entry is always at the **end** of the array.

For `OfferCSV`, the format is **triplets** (time, price, shipping):
```
offerCSV = [t0, price0, ship0, t1, price1, ship1, ...]
```
- `shipping` codes: `-2` = unknown, `-1` = unshippable / not specified, `0` = free, otherwise cents.
- Newest: `price` at `[length-2]`, `shipping` at `[length-1]`.

| Idx | Const | Meaning |
|---|---|---|
| 0 | `AMAZON` | Amazon's own offer price (what Amazon charges direct) |
| 1 | `NEW` | Lowest 3rd-party new offer (no shipping) |
| 2 | `USED` | Lowest used offer |
| 3 | `SALES` | Sales rank in primary category (lower = better) |
| 4 | `LISTPRICE` | MSRP / list price |
| 5 | `COLLECTIBLE` | Lowest collectible offer |
| 6 | `REFURBISHED` | Lowest refurbished offer |
| 7 | `NEW_FBM_SHIPPING` | Lowest NEW FBM offer with shipping |

### 4.5 Decoding helpers (drop into `lib/keepa/decode.ts`)

```ts
import { keepaMinutesToUnixMs } from "./types";

/** Decode a flat csv pair-array into [{ at, value }] points. -1 = null. */
export function decodePriceHistory(csv: number[] | null | undefined) {
  if (!csv) return [];
  const out: { at: number; value: number | null }[] = [];
  for (let i = 0; i < csv.length; i += 2) {
    out.push({
      at: keepaMinutesToUnixMs(csv[i]),
      value: csv[i + 1] === -1 ? null : csv[i + 1] / 100, // cents -> dollars
    });
  }
  return out;
}

/** Decode an offerCSV (triplets) into [{ at, price, shipping }] points. */
export function decodeOfferCSV(csv: number[] | null | undefined) {
  if (!csv) return [];
  const out: { at: number; price: number | null; shipping: number | null }[] = [];
  for (let i = 0; i < csv.length; i += 3) {
    const price = csv[i + 1];
    const ship  = csv[i + 2];
    out.push({
      at: keepaMinutesToUnixMs(csv[i]),
      price: price === -1 ? null : price / 100,
      shipping: ship < 0 ? null : ship / 100,
    });
  }
  return out;
}

/** Get the latest non-null value for a csvType from a Product. */
export function latestPrice(product: { csv: (number[] | null)[] }, csvType: number): number | null {
  const arr = product.csv[csvType];
  if (!arr || arr.length === 0) return null;
  for (let i = arr.length - 1; i >= 1; i -= 2) {
    if (arr[i] !== -1) return arr[i] / 100;
  }
  return null;
}
```

## 5. Rate Limits

- **Token bucket** is the only per-account rate limit — there is no separate RPS cap published. Keepa's docs say "the API itself imposes no concurrency cap, but burning past zero tokens returns 429."
- **Recommended concurrency: 4–8 parallel requests.** Higher concurrency rarely helps because most of our calls are 1-token reads and we'll exhaust the bucket fast.
- **HTTP 429** response: includes `tokensLeft: 0`, `refillIn: <ms>`. Back off and retry after `refillIn` ms.
- **HTTP 503** indicates server-side overload — retry with exponential backoff, max 3 attempts.
- **No daily cap** beyond the token bucket regeneration rate.

**Client behavior for PharmaDash:**
```ts
// lib/keepa/client.ts (sketch)
async function callKeepa<T>(path: string, params: Record<string, string>): Promise<T> {
  for (let attempt = 0; attempt < 3; attempt++) {
    const res = await fetch(buildUrl(path, params));
    const json = await res.json();
    if (res.status === 200 && json.tokensConsumed >= 0) return json as T;
    if (res.status === 429 && json.refillIn) {
      await sleep(json.refillIn + 250);
      continue;
    }
    if (res.status >= 500) {
      await sleep(1000 * 2 ** attempt);
      continue;
    }
    throw new KeepaError(res.status, json);
  }
  throw new KeepaError(-1, { message: "exhausted retries" });
}
```

Add a **token-aware semaphore** in front of `callKeepa` to refuse calls when `tokensLeft < estimatedCost` and resolve once refill catches up. Track `tokensLeft` from the last response for cheap predictions.

## 6. Webhook Event Shape (Repricer subscription)

When a tracking threshold fires, Keepa POSTs a `Notification` JSON to our registered URL.

**Endpoint design** (PharmaDash side, Render web service):
```
POST /api/keepa/webhook
Body: { ...Notification }
```

**Verification:** Keepa does not sign payloads. We use **`metaData` as a shared secret + correlation key** when registering the tracking. Format: `pharm1:<listingId>:<HMAC-of-asin-with-secret>`. On webhook receipt:
1. Parse `metaData`, verify HMAC.
2. Look up `listingId` in `pending_listings`.
3. Idempotency check on `(asin, notificationType, createDate)`.
4. Convert `createDate` to UTC, store in `keepa_notifications`.
5. Enqueue minicrew `repricer.evaluate` job with the listing id.

**Important latency:** Keepa polls products at the `updateInterval` we set (1 hour minimum on Starter). So "Buy Box just dropped" can be up to 1 hour stale. For sub-hour reaction, we'd need to short-poll `/product` ourselves — but at Starter's 20 tok/min that's 30 ASINs × 24 fetches/day = 720 tokens/day, easily within budget. **Recommendation: hybrid — webhooks as the safety net, plus our own 15-minute pollers on the top ~10 listings.**

**Recommendation:** Write our own thin client at `lib/keepa/client.ts`. Estimated scope: ~250 LOC for client + types + decoders. The Java struct files in `keepacom/api_backend/structs/*.java` are the closest thing to a spec — translate them directly into TS interfaces.

## 8. Fixture Data for Testing

We cannot rely on the live API in tests — it'd burn tokens and require network. Recommended approach:

### 8.1 Capture-and-replay

1. Once `KEEPA_API_KEY` is in env, write a one-off script `scripts/keepa-capture.ts` that:
   - Calls `/product` for 3 representative ASINs (one with rich offer history, one stock-out-prone, one stable Amazon-direct).
   - Calls `/deal` once with realistic filters.
   - Calls `/bestsellers` for one Health & Household subcategory.
   - Saves raw JSON responses to `tests/fixtures/keepa/*.json`.
2. Store decoded variants alongside (after running through `decode.ts`) so tests can assert on either layer.
3. Add a `keepa-capture-redacted.ts` step that scrubs `tokensLeft` / `timestamp` / our seller IDs before commit.

### 8.3 Mock server pattern

For integration tests, run a `msw` (Mock Service Worker) handler that returns the captured JSON for known ASINs and a 429 for unknown ones — exercises both happy path and error path without network.

```ts
// tests/mocks/keepa-handlers.ts
import { http, HttpResponse } from "msw";
import productB07 from "../fixtures/keepa/product-B07XJ8C8F5.json";

export const keepaHandlers = [
  http.get("https://api.keepa.com/product", ({ request }) => {
    const url = new URL(request.url);
    const asin = url.searchParams.get("asin");
    if (asin === "B07XJ8C8F5") return HttpResponse.json(productB07);
    return HttpResponse.json(
      { tokensLeft: 0, refillIn: 60000, error: "not found" },
      { status: 404 }
    );
  }),
];
```

## Relevance to PharmaDash

- **Wave 2 (Repricer):** Lives or dies by the `BUY_BOX_SHIPPING` (csv index 18) signal + `AMAZON` (0) + `NEW_FBA` (10) for the FBA-trust-premium math the platform is built around. Tracking webhooks + 15-min self-poll on top listings is the right hybrid. Token budget: **~150 tokens/day** comfortable.
- **Wave 3 (Research Analyst):** `/deal` endpoint is the cheapest discovery path (5 tokens/page × 1–2 pages/day = 10 tokens). `/bestsellers` once per week per category to refresh the watch list. `/product` lookups (1 token each) for shortlisted ASINs.
- **Token budget at $54/mo Starter is comfortable.** ~1,200 tokens/hr ceiling, ~200 tokens/day projected need. Headroom for 6× growth before plan upgrade.
- **No official TS SDK → write ours.** ~250 LOC at `lib/keepa/`, structured as `client.ts` + `types.ts` + `decode.ts` + `webhook.ts`. Use the Java struct files in `keepacom/api_backend` as the canonical spec.
- **Webhook security:** Keepa does not sign payloads. Use `metaData` as a HMAC-tagged correlation key — set on tracking registration, verify on webhook receipt.
- **Cache behavior is in our favor:** `update` parameter on `/product` returns cached data without burning tokens if data is fresh enough. Set `update=2` for Repricer (2-hour staleness OK) and `update=24` for Research Analyst.
- **Two-POS isolation invariant intact:** Keepa is OTC-only by virtue of the ASINs we feed it. No PHI surface.
